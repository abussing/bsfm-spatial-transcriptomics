# Canonical full-cell S10 preparation gate

Status: **accepted canonical preparation implementation**. Review baseline:
`0c5bed151def7c2ae429c0bc894cdb3aead96251`, the accepted Layer-9A design
checkpoint. The v1 artifacts below were generated by uncommitted review code
and remain review evidence only. Canonical regeneration under the clean accepted
preparation commit is required. This gate does not implement Layer-9 initialization, adaptation,
transactions or Gibbs sweeps. No accepted numerical source or environment changes.

The user explicitly authorized one S10 mechanical input/GPINIT gate with K=20,
nfit=250 and seed=2026102610. These are not production defaults or a factor-count

## Boundary and implementation

- [s10_preparation.py](../../src/bsfm/initialization/s10_preparation.py) authenticates
  the six-file response and production receipts, checks all response dataset
  identities, authenticates the raw H5AD and reads metadata only, verifies the
  exact full-cell mesh join, and writes the seven-array NPZ plus extended
  `bsfm.gpinit-input.v1` contract. It does not read raw expression counts, run R,
  recorrect counts, center Y or fit a GP.
- [preparation_environment.py](../../src/bsfm/initialization/preparation_environment.py)
  authenticates the already accepted environments before numerical imports.
  It installs nothing and permits no user/system-site fallback.
- [s10_gpinit_gate.py](../../src/bsfm/initialization/s10_gpinit_gate.py) calls the
  unchanged accepted `gp_svd.fit` and `gp_svd.save`, pins their accepted source
  and configuration hashes, independently reopens the result and checks its
  identities and factorization. It adds evidence, not another GP algorithm.
- [s10-prepared-input.schema.json](../../schemas/initialization/s10-prepared-input.schema.json)
  defines the S10-specific provenance extension; numerical/identity validation
  is separate from structural JSON validation.
- [test_s10_preparation.py](../../tests/test_s10_preparation.py) tests exact
  identity preservation and rejection of values, order, types, duplicate or
  fabricated IDs, nonfinite responses, historical half-population and mesh
  permutation corruption. Existing GPINIT tests remain unchanged.

The input artifact's `producer.baseline_commit` is the committed design
checkpoint. `generating_commit=null` and `worktree_clean=false` honestly record
that the preparation adapter is uncommitted review code. Exact executed source
hashes are retained. A later acceptance commit cannot retroactively become the
artifact's generating commit. The GP fitting implementation itself is committed
and pinned; its orchestration wrapper is also uncommitted review code.

## Validation policy fixed before fits

Same-environment repeated output arrays, fitting indices, smoothed-surface
hash, singular values and numerical diagnostics must match exactly. Timings
and serialization bytes need not match. All seed arrays must be finite and
have Lam_seed[3,91,20] and eta_seed[20,9422].

Independent saved-result checks use the accepted GP tests' `1e-13` loading
orthogonality and eta-mean checks. Additional diagnostic algebra checks use
relative `1e-12` for eta's Gram matrix versus the leading singular squares,
the reconstructed product norm versus the leading singular-value norm, and
the reported truncation norm versus the discarded singular-value norm divided
by max(1, surface norm). These are saved-factorization checks, not changes to
fitting settings or claims of scientific fit accuracy. The complete 273-row
smoothed matrix is not retained; its existing accepted logical hash and repeat
comparison remain in the certificates.

No byte/numerical equality is expected with the historical half-cell result.
The preparation and output validators must explicitly reject that population.
Neither K=20 nor these mechanical checks select a posterior model or demonstrate
mixing, convergence, predictive accuracy, or primary holdout eligibility.
